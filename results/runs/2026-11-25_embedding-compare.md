# 임베딩 모델 비교 (구성 A)

- 일시: 2026-11-25
- 담당: 서종찬
- 평가셋: `eval/eval-dev.json` 8문항 (`no_answer` 2문항 제외)
- 재현: `python src/compare_embeddings.py text-embedding-3-small text-embedding-3-large`

## 측정 설계

**구성 A(벡터 단독)로 쟀다.** 구성 B 는 BM25 가 섞여 모델 차이를 가린다.
dev 에서 구성 B 는 이미 8/8 이라 어떤 모델을 넣어도 8/8 이 나왔을 것이다.

**Hit@5 외에 정답 청크의 순위를 같이 봤다.** Hit@5 는 1위로 찾은 것과
5위로 겨우 찾은 것을 똑같이 `O` 로 처리한다. 문항이 8개뿐이라 그 해상도로는
모델 간 차이를 판단할 수 없다. MRR(= 1/순위 의 평균)은 연속적인 값이라
같은 8문항에서 훨씬 많은 정보를 끌어낸다.

## 결과

```
모델                        차원   Hit@5     MRR   정답 순위
text-embedding-3-small     1536     6/8   0.427     2  6  3  2  2  12  3  1
text-embedding-3-large     3072     7/8   0.701     1  2  2  1  1   9  2  1
                                                  001 002 003 004 005 006 007 008
```

| | 3-small | 3-large |
| --- | --- | --- |
| Hit@5 | 6/8 | **7/8** |
| MRR | 0.427 | **0.701** |
| 1위로 찾은 문항 | 1 | **4** |
| 전량 임베딩 비용 | ~$0.01 | ~$0.1 |
| 임베딩 소요 | 9.4초 | 13.8초 |

## 읽는 법

**8문항 전부에서 3-large 가 같거나 앞선다. 진 문항이 하나도 없다.**
이것이 Hit@5 차이(6 vs 7)보다 중요하다. 한 문항 차이는 우연일 수 있지만,
8문항 모두에서 밀리지 않는 것은 우연으로 보기 어렵다.

표본이 8개라 MRR 0.427 과 0.701 의 **절대값**은 믿을 게 못 된다.
믿을 수 있는 건 **방향이 일관되다는 사실**이다.

## 모델을 키워도 안 되는 것

DEV-006 은 두 모델 모두 실패했다(12위, 9위).
`D-2-2`(학사)와 `D-2-3`(석사) **각각의** 허용 시간을 묻는 문항이다.

차원을 2배로 늘려도 9위가 한계였다. **벡터 방식 자체의 한계지 모델 품질 문제가 아니다.**
BM25 는 이 문항을 맞혔다(기준선에서 O). 보호 토큰이 코드를 통째로 지켰기 때문이다.

하이브리드가 필요한 이유가 여기서 한 번 더 확인된다.
좋은 임베딩 모델을 고르는 것으로는 이 구멍을 못 메운다.

## 결론

**`text-embedding-3-large` 를 쓴다.**

비용이 10배지만 절대액이 $0.1 대 $0.01 이다. 전량 재임베딩을 열 번 해도 1달러다.
이 규모에서 비용은 선택 기준이 되지 못한다.

## 돌리지 못한 모델

- `text-embedding-ada-002` : 학원 프로젝트 계정에 접근 권한 없음 (403)
- `BGE-m3`, `KURE-v1` : `sentence-transformers`(PyTorch 2~3GB) 설치 필요.
  한국어 검색 벤치마크(MTEB-ko)에서 KURE-v2 0.816 > KURE-v1 0.762 > BGE-m3 0.751 이나,
  **그 리더보드는 상용 API 모델을 제외하므로 OpenAI 와 직접 비교한 공개 수치는 없다.**
  설치 부담과 팀원 환경을 고려해 보류. 시간이 되면 측정 가치가 있다.
