## 결론: BM25 의 적중은 벡터 적중의 부분집합이다

```
test   BM25 적중 9개   001 002 006 007 009 011 015 016 017
       벡터 적중 15개  001 002 004 005 006 007 008 009 010 011 012 014 015 016 017
                      -> BM25 가 맞힌 9개가 전부 포함된다

dev    BM25 적중 3개   002 006 007   -> 벡터는 8개 전부 적중
```

BM25 가 **추가로 건지는 문항이 없다.** 벡터가 놓친 TEST-003(15위)·TEST-013(밖) 은
BM25 도 7위·밖으로 못 찾는다. 합쳐도 못 찾는 건 같고, 잘 찾던 것을 밀어내기만 한다.

BM25 가 벡터보다 순위가 나은 유일한 경우는 TEST-007 (BM25 1위 / 벡터 3위) 뿐이다.

## 왜 BM25 가 약한가

이 매뉴얼은 39개 문서가 모두 같은 절 구조를 갖는다.

```
유학(D-2)      > 제출서류 / 허가기준 / 신청요령 / 체류기간 연장허가
일반연수(D-4)   > 제출서류 / 허가기준 / 신청요령 / 체류기간 연장허가
구직(D-10)     > 제출서류 / 허가기준 / 신청요령 / 체류기간 연장허가
```

"체류기간 연장허가 제출서류" 같은 질의는 39개 문서 전체에 걸린다. 어휘에 변별력이
없다. DEV-001 이 20위 밖, TEST-008 이 16위인 것이 이 양상이다.
벡터는 "D-4 어학연수생" 이라는 맥락을 반영하므로 해당 문서를 집어낸다.

## RRF 동등 가중의 문제

RRF 는 점수를 버리고 순위만 쓴다. 그래서 **검색기의 품질 차이도 함께 버린다.**
품질이 2배 차이나는 두 검색기를 동등 가중으로 합치면 약한 쪽으로 끌려간다.
w=0.5, w=0.3 으로 낮춰도 A 를 넘지 못했다 (0.766 / 0.745 vs 0.792).

다만 **dev 8문항에서 0.766 과 0.745 의 차이는 신뢰할 수 없다.** 한 문항이 한 칸
움직이면 그만큼 흔들린다. 신뢰할 수 있는 것은 "A 가 모든 B 변형보다 높다" 와
"dev 와 test 가 같은 결론" 두 가지다.

## 남은 실패 (구성 A)

- **TEST-003** (15위) 구직(D-10) 자격변경. BM25 는 7위. 어휘 단서는 있으나 둘 다 top5 밖.
- **TEST-013** (밖) "알바하는 가게가 바뀌면" → 정답 p.38 「(3) 장소변경」.
  의미적으로 「근무처의 변경·추가」 로 끌려간다. BM25 도 못 찾는다.
