# 후보 재현율 — 재정렬 앞단을 무엇으로 할 것인가

날짜: 2026-11-26 / 색인 idx-v5 (청크 1,815) / 평가셋 eval-test-quoted.json (채점 17문항)

## 왜 쟀나

재정렬은 후보를 다시 줄 세울 뿐 새로 찾아오지 않는다. 그래서 재정렬 앞단을 고를 때
중요한 것은 상위 5 순서가 아니라 **후보 20개 안에 정답이 있는 비율**이다.

구성 B 는 상위 5 에서 A 보다 낮았지만(13/17 vs 15/17), 후보 단계에서는 RRF 가
재현율을 올려 줄 가능성이 있었다. 그것을 확인했다.

## 결과

| 구성 | Hit@20 (후보 재현율) | Hit@5 | MRR |
|---|---|---|---|
| A 벡터 단독 | **16/17** | **15/17** | **0.774** |
| B BM25+벡터 RRF | **16/17** | 13/17 | 0.679 |

**재현율이 같다.** 둘 다 TEST-013 하나만 후보에서 놓친다.
B 는 후보를 더 건져오지 않고 순서만 흐트러뜨렸다.

→ 가설 기각. **재정렬 앞단으로도 A 를 쓴다.** 구성 B 는 어느 단계에서도 쓸 이유가 없다.

## 재정렬의 천장

```
후보 20개 안에 정답 있음   16/17
상위  5개 안에 정답 있음   15/17
                        ─────
재정렬이 끌어올릴 수 있는 것   1문항
```

**완벽한 재정렬기를 써도 15/17 -> 16/17 이 최대다(+5.9%p).**
해당 문항은 TEST-003 (구직 D-10 자격변경, 구성 A 에서 15위).

TEST-013 은 후보 20개 안에도 없으므로 재정렬로는 해결되지 않는다.
검색 자체를 고치거나(질의 재작성, 청킹 조정) 다른 접근이 필요하다.

## 비용과 견주면

박태환의 dev 측정(`2026-11-26_test-report.md`)과 겹쳐 본다.

| | 값 |
|---|---|
| 최대 이득 | +1문항 (+5.9%p) |
| 실측 비용 | 응답 시간 중앙값 2.46초 -> 18.66초 (**7.6배**) |
| 실측 결과 | dev 에서 A 8/8 -> C 6/8 (**2문항 손해**) |

다만 그 C 는 B 를 앞단으로 쓴 결과다. **A 를 앞단으로 한 C 는 아직 재지 않았다.**
천장이 1문항이므로 재더라도 얻을 수 있는 최대치는 변하지 않는다.

## 남은 실패 2건

- **TEST-003** (A 15위, B 9위) — 후보에는 있다. 재정렬이 노릴 수 있는 유일한 문항.
- **TEST-013** (양쪽 다 후보 밖) — "알바하는 가게가 바뀌면" -> 정답 p.38 「(3) 장소변경」.
  의미적으로 「근무처의 변경·추가」 쪽으로 끌려간다. 재정렬로는 해결 불가.

## 재현

```
python src/retrieve.py --config A --eval eval/eval-test-quoted.json --top-k 20
python src/retrieve.py --config B --eval eval/eval-test-quoted.json --top-k 20
```
