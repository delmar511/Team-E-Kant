| 발행 | 법무부 출입국·외국인정책본부 |

`-layout` 을 쓴 이유: 이 문서는 2단 표 레이아웃이라 들여쓰기가 계층 정보를 담고 있다. 기본 모드는 줄바꿈이 더 심하게 깨진다.

## 2. 문서 구조

왼쪽 열에 **업무 구분**, 오른쪽 열에 **내용**이 들어간 표다.

```
별도 허가 없이      외교(A-1)~협정(A-3), 문화예술(D-1), ...
유학활동이 가능한    교수(E-1)~특정활동(E-7), ...
체류자격            (F-1)~결혼이민(F-6), ...
   ↑ 왼쪽 열 (3줄에 걸쳐 쪼개짐)    ↑ 오른쪽 열 (본문)
```

왼쪽 조각을 이어 붙이면 `별도 허가 없이 유학활동이 가능한 체류자격` — 이것이 섹션 제목이다. 따라서 **업무명 목록을 미리 정의해두고 줄 앞부분을 잘라내 헤딩으로 승격**시킨다.

### 인식하는 업무 구분 14종

```
자격 해당자 및 활동범위 / 1회에 부여할 수 있는 체류기간 상한 /
별도 허가 없이 ~활동이 가능한 체류자격 / 체류자격외 활동 / 시간제취업 /
활동 허가 제한대상 / 체류자격 부여 / 체류자격 변경허가 / 체류기간 연장허가 /
근무처 변경·추가 / 재입국허가 / 외국인등록 / 사증발급인정서
```

### 계층 매핑

| 마크다운 | 원문 |
|---|---|
| `#` | 체류자격 (유학(D-2)) |
| `##` | 업무 구분 (체류기간 연장허가) |
| `###` | `1.` `2.` 번호 항목 |
| `####` | `가.` `나.` `다.` 항목 |

## 3. 적용한 전처리 규칙

| # | 규칙 | 이유 |
|---|---|---|
| R1 | `~ 목차` 줄 제거 | 페이지마다 반복되는 목차 링크. 검색 노이즈 |
| R2 | `- 34 -` 형태 페이지 번호 줄 제거 | 머리글·바닥글 |
| R3 | 연속 공백 2칸 이상 → 1칸 | PDF 양쪽정렬로 생긴 과다 공백 |
| R4 | 자간 벌림만 붙임 (`유 학` → `유학`) | 20자 이하 + 한 글자 단위 분리가 3회 이상인 줄에만 적용. **단어 사이 한 칸은 보존** |
| R5 | `E- 7` → `E-7` 정규화 | 이 판에는 5회뿐이나, 사증민원 매뉴얼은 438회 발생. 다른 판 대비 |
| R6 | 유니코드 하이픈(`‐‑–`) → ASCII `-` | 체류자격 코드 매칭 일관성 |
| R7 | 페이지 상단 자격 제목 줄 제거 | `#` 헤딩과 중복 |

**검증**: D-2 구간(p.35~55) 기준 원문 한글 10,296자 → 변환본 9,912자(**96.3%**). 손실분은 위 규칙으로 제거한 노이즈다.

## 5. 청킹 규칙

| 항목 | 결정 | 근거 |
|---|---|---|
| 기본 단위 | `####` (가./나./다. 항목) | 질문 하나에 대응하는 크기. `##`은 2~5천 자로 임베딩이 희석됨 |
| `####` 없는 구간 | `###` → `##` 순으로 대체 | |
| 최대 길이 | 1,200자 초과 시 줄 경계로 분할 | 임베딩 입력 한도 |
| 최소 길이 | 공백 제외 20자 미만 버림 | 페이지 조각 |
| 겹침(overlap) | **없음** | 구조 기반 청킹이라 의미 단위가 완결됨 |
| 상위 제목 | 버리지 않고 `location` 필드로 보존 | 맥락 유지 |

### chunk_id 생성

```
SHA1(doc_id + '|' + 제목경로 + '|' + 본문 앞 200자)[:10]
```

**결정적이다.** 같은 입력을 두 번 돌리면 같은 ID가 나온다. 랜덤 UUID를 쓰지 않은 이유는 평가셋의 `gold_chunks`가 재생성 때마다 깨지면 안 되기 때문이다 (평가표 3번 *"동일 조건으로 재생성할 수 있는가"*).

### 결과 (D-2 구간)

```

```

## 수정 6 — 2단 표의 본문이 엉뚱한 항목에 붙던 문제 (2026-11-24)

### 증상

`외교(A-1)` 의 「자격 해당자 및 활동범위」 본문이 "…받는 자와 그" 에서 끊기고,
이어지는 "가족" 이 다음 항목인 「1회에 부여할 수 있는 체류기간 상한」 밑에 붙었다.

### 원인

원문 14쪽 레이아웃:

```
  3|             대한민국정부가 접수한 … 조약      ← 본문
  4|자격 해당자                                  ← 항목명 조각
  5|             또는 국제관행에 따라 … 받는 자와 그  ← 본문
  6|및 활동범위                                  ← 항목명 조각
  7|             가족                            ← 본문
  9|1회에부여할 수                               ← 다음 항목명 조각
 10|              재임기간                        ← 다음 항목 본문
 11|있는 체류기간 상한
```

항목명은 제 본문의 **세로 한가운데**에 놓이므로 조각(4·6행) 사이에 본문(5행)이
끼어들고, 항목명이 끝난 뒤에도 본문(7행)이 더 내려온다.
기존 변환기는 항목명이 완성되는 순간(6행) 제목을 쓰고 넘어가서,
7행이 다음 구간으로 밀렸다. 왼쪽 칸만 있는 줄이 전체 16,683줄 중 1,583줄이라
거의 모든 항목 경계가 영향을 받았다.

같은 이유로 `유학(D-2)` 은 「자격 해당자」 **첫 줄**("(교육기관) 「고등교육법」 및
특별법에 따라 설립된 전문대학 이상의")이 통째로 빠져 있었다.
항목명 시작 조각과 같은 줄에 있던 본문이 버려졌기 때문이다.

### 조치

한 쪽을 두 번 읽는 구조로 바꿨다.

1. `column_split()` — 들여쓰기로 각 줄을 (왼쪽 항목명 칸, 오른쪽 본문 칸)으로 나눈다.
   `pdftotext -layout` 이 가로 위치를 공백으로 보존하는 성질을 그대로 쓴다.
2. `find_labels()` — 왼쪽 조각을 모아 항목명과 그 **줄 범위**를 구한다.
   사이에 본문 줄이 끼어도 누적이 이어진다. 항목명이 아닌 것으로 판명된 조각은
   본문으로 되돌린다.
3. 본문 줄을 **세로로 가장 가까운 항목명**(줄 범위의 중앙값)에 배정한다.
   항목명보다 위에 있는 첫 줄도 그 항목의 것이 된다.

항목명이 하나도 없는 쪽은 직전 구간이 이어지는 것으로 본다(종전과 동일).

### 결과

| | 전 | 후 |
|---|---|---|
| 본문 총 글자 | 598,456 | 603,762 |
| 청크 | 1,494 | 1,520 |

누락됐던 본문이 돌아오면서 글자 수가 늘었다. 문장을 새로 만들어낸 것은 없다.

## 알려진 한계 L5

본문 배정이 "가장 가까운 항목명" 이라는 **추정**에 기대고 있다.
원문 표의 실제 칸 경계선(괘선)을 읽는 것이 아니므로, 한 항목의 본문이
다음 항목명의 중앙선을 넘어갈 만큼 길면 잘못 배정될 수 있다.
표본 점검(A-1 14쪽, D-2 35·45쪽)에서는 문제가 없었으나 전수 확인은 하지 않았다.
정확히 하려면 `pdfplumber` 등으로 괘선 좌표를 읽어야 한다.


## 수정 8 — 본문 배정을 '거리'가 아니라 '구간'으로 (2026-11-24)

수정 6 의 '가장 가까운 업무명(줄 범위의 중앙)' 규칙은 본문이 업무명보다
훨씬 길면 뒤쪽 업무명으로 끌려간다.

`유학(D-2)` 35쪽:

```
  1|자격 해당자 및   (교육기관) ...        ← 업무명 1~2행, 중앙 1.5
 16|             적용대상별 세부약호        ← 본문이 27행까지 이어짐
 27|  (D-4)       D-4-7   외국어 연수
 28|1회에부여할 수있는                      ← 업무명 28·30행, 중앙 29
 29|             2년
 30| 체류기간 상한
```

16~27행은 1.5 보다 29 에 가까워 「체류기간 상한」 으로 넘어갔다.
세부약호 표(D-2-1 ~ D-4-7) 전체가 엉뚱한 항목에 붙은 것이다.

**규칙 변경**: 한 업무의 영역 = 그 업무명이 시작하는 줄 ~ 다음 업무명이
시작하기 직전. 업무명이 본문의 세로 한가운데에 놓이므로, 첫 업무명보다
3줄 이내로 위에 있는 본문도 그 구간에 넣는다. 그보다 더 위는 앞 쪽에서
이어지는 본문으로 보고 직전 구간에 흘린다.

A-1(본문 3줄)과 D-2(본문 27줄) 양쪽에서 맞는다.

## 수정 9 — 표의 칸 경계 보존

`squash()` 가 자간 벌림을 붙일 때 공백 길이를 가리지 않아

## 수정 10 — 평가셋 대조로 드러난 문제 (2026-11-25)

평가셋 초안(`eval/eval-dev.json`)의 근거 41건을 코퍼스와 대조해 네 가지를 찾았다.
대조 전에는 41건 중 0건만 맞았다.

### 10-1. 형제 항목이 부모-자식으로 엮임

```
(잘못) 유학(D-2) > 체류기간 연장허가 > 가. 기본원칙 > 다. 제출서류
(바름) 유학(D-2) > 체류기간 연장허가 > 다. 제출서류
```

`가./나./다.` 는 같은 수준이다. `chunk.py` 가 `path[:level-1]` 로 경로를 자르는데,
`##` 다음에 `###` 없이 `####` 가 오면 실제 깊이와 제목 수준이 어긋나 형제가 중첩됐다.
제목 수준 스택을 따로 두어 같거나 깊은 수준을 걷어내고 쌓도록 바꿨다.

### 10-2. 항목명 변형을 놓침

| 원문 | 기존 목록 | 결과 |
| --- | --- | --- |
| `시간제취업 / 활동 허가` | `시간제취업` | 뒷부분이 본문으로 샘 |
| `활동범위 및 / 자격 해당자` (D-4 는 어순이 반대) | 없음 | 구간 자체를 못 찾음 |
| `근무처의 / 변경·추가` | `근무처 변경·추가` | 20개 문서에서 못 찾음 |

원문의 `·` 가 사설영역 글리프(U+F024)로 깨져 있는 것도 원인 중 하나였다.
항목명 비교 시 사설영역 문자를 제거하도록 했다.

### 10-3. 제목의 자간 벌림

`나. 대    상` 이 `나. 대 상` 으로 남아 평가셋의 `나. 대상` 과 달랐다.
수정 9 에서 표의 칸 경계를 지키려고 두 칸 이상 공백을 보존했는데,
제목에는 그 규칙이 맞지 않는다. 제목은 공백으로 나눈 조각이 전부 한 글자일 때만 붙인다
(`대 상` -> `대상`, `허가 기준 등` 은 그대로).

### 10-4. 663쪽 이후가 빠져 있었음

원문은 796쪽인데 662쪽까지만 변환했다. 평가셋 10문항 중 3문항이
`광역형 비자 시범사업`(705~796쪽)을 근거로 쓴다. 두 문서를 추가했다.

- `DOC-ANNEX` 붙임 서식 및 취업제한분야 (663~704쪽)
- `DOC-WIDE` 광역형 비자 시범사업 (705~796쪽)

### 결과

문서 34 -> 36개, 청크 1,498 -> 1,646개.
평가셋 근거 41건 중 인용문이 코퍼스에서 발견되는 비율: 0 -> 35건(전체 32, 일부 3).

남은 6건은 코퍼스 문제가 아니다. 평가셋 인용문에 `...` 생략 부호가 들어갔거나(2건),
표의 칸을 ` / ` 로 이어붙여 원문과 글자가 달라졌거나(3건),
변환 범위 밖인 안내문(1~13쪽)을 가리킨다(1건).

## 알려진 한계 L7

평가셋의 `section` 은 사람이 읽는 자유 형식이라 `location` 과 글자 그대로 맞지 않는다
(`체류자격외 활동 > 3`, `나~다`, `유의사항` 등). `chunk_id` 를 채울 때는
`section` 이 아니라 `quote` 를 코퍼스 본문에서 찾는 방식을 써야 한다.

## 알려진 한계 L8

본문이 없는 제목은 청크가 되지 않아 코퍼스에서 사라진다.
예: 일반연수(D-4) 의 `1. "유학(D-2) 자격 체류자격외 활동 허가" 참조` 는
제목만 있고 아래에 본문이 없어서 어떤 청크의 location 에도 남지 않는다.
평가셋이 이런 제목을 근거로 지목하면 chunk_id 를 채울 수 없다.
해결하려면 제목 자체를 본문으로 가진 청크를 만들어야 하는데,
짧은 청크가 늘어나는 것과 맞바꿔야 해서 평가 결과를 보고 정한다.

## 수정 11 — 앞부분 유의사항·공통사항 추가 (2026-11-25)

### 증상

1~13쪽에 청크가 없었다. DEV-009 의 참고 근거(p.3 유의사항 "허가 여부는 심사에 의해 결정될 수 있습니다")가
색인에 없어 `chunk_id` 를 채울 수 없었다. 이 구간에는 모든 자격에 공통으로 적용되는
심사수수료, 여권 유효기간 내 체류기간 부여, 직업·소득 신고, 재학증명서 제출, 결핵진단서 제출 규정도 있다.

### 조치

`DOC-INTRO` 유의사항 및 공통사항 문서를 추가했다. 변환기는 `src/ingest/intro_to_md.py` (전용).

| 쪽 | 내용 | 처리 |
|---|---|---|
| 1 | 표지 | 제외 |
| 2 | 목차 | 제외 (검색 노이즈) |

| 4 | 공통사항 목차 | 포함 (짧은 청크 1개) |

| 6–8 | 공통사항 1~4 | 포함 |

`pdf_to_md.convert` 를 쓰지 않은 이유: 2단 표용 규칙이라 유의사항의 `1. ...` 번호 항목을
`###` 제목으로 올려 문장이 반으로 잘리고, 뒷부분이 20자 미만이면 청킹에서 버려진다.
전용 변환기는 쪽마다 주제를 `##` 로 두고 줄바꿈으로 잘린 문장을 잇는다.
공백·비자코드 정리(`squash`, `norm_code`, `NOISE`)는 `pdf_to_md` 것을 그대로 쓴다.

**심사수수료 표(p.5).** `-layout` 추출은 업무명과 수수료 칸이 어긋난다. `pdftotext -raw`
(내용 스트림 순서)로 업무명-수수료 짝 15개를 얻고 `-table`·`-simple` 출력과 행마다 대조해

감액 행으로 읽었다 (8만→4만, 6만→3만). 근거 법령 칸은 병합 셀이라 행 배정을 확정할 수 없어 표 아래에 함께 적었다.
`[확인 필요]` 원문 PDF 화면으로 한 번 대조할 것.

**쪽 표시 위치.** `chunk.py` 는 청크를 내보내는 시점의 `page` 를 기록하므로, 쪽 표시가 `##` 앞에 오면

## 알려진 한계 L9

`chunk.py` 는 쪽 표시(`<!-- page: N -->`)를 만나면 바로 `page` 를 바꾸고, 버퍼는 다음 제목에서 내보낸다.
그래서 쪽 표시 직후에 제목이 오면 그 앞 절 청크가 한 쪽 뒤 번호로 기록된다. 기존 문서에 129군데.
`page` 는 `chunk_id` 해시에 들어가지 않으므로 고쳐도 ID 는 바뀌지 않지만, 인용 쪽 번호와
평가셋의 `page` 대조가 달라질 수 있어 따로 확인 후 고친다.
